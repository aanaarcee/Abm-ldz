# Migraciones

Cada cambio de estructura (tabla nueva, columna nueva, índice, etc.) va en **un archivo nuevo** de esta carpeta:

    003_agregar_telefono_persona.sql
    004_tabla_notificacion.sql

- Se aplican **en orden de nombre**, cada una **una sola vez**. El servidor lo anota en la tabla `EsquemaMigracion`.
- Se aplican solas cuando se abre la aplicación (cada migración va en una transacción: si falla, no queda nada a medias).
- Si el archivo tiene varios bloques, se separan con una línea que diga solo `GO`.
- **No edites ni renombres una migración ya aplicada** (no se vuelve a correr): corregila con una migración nueva.
- `sql/OficinaRegistros.sql` es la estructura de partida: no se toca para cambiar tablas. Solo se editan ahí las
  funciones de búsqueda (`sp_BuscarGeneral`, `f_coincide`). Se vuelven a crear solas después de las migraciones,
  así que pueden usar columnas que agregó una migración.
- Para que una base ya creada reciba un cambio en la búsqueda, hace falta una migración nueva (aunque sea solo un
  comentario, como la `002`): las funciones se recrean cuando se aplica alguna.
- Un cambio de tablas casi siempre pide también cambiar el código de `Oficina.Entidades` y de
  `Oficina.Datos/Postgres/PgDatos*.cs` (y `Memoria/DatosEnMemoria.cs` si hace falta para el modo prueba).

Ejemplo (004_tabla_notificacion.sql):

    CREATE TABLE Notificacion (
        IdNotificacion INT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
        IdActa         INT NOT NULL REFERENCES Acta(IdActa),
        Fecha          DATE NOT NULL
    );
    GO
    CREATE INDEX IX_Notificacion_Acta ON Notificacion(IdActa);
